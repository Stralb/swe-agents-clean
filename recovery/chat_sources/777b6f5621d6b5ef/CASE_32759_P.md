Windows: relay.mjs fails when default temp output path contains spaces

Hi, I found a Windows compatibility issue in `codex-delegate/scripts/relay.mjs`.

## Summary

On Windows, `codex-delegate` can fail when the relay uses its default output directory under the system temp path and that path contains spaces.

Example user profile path:

```text
C:\Users\Mahmoud Sabry\...
```

The relay fails with:

```text
error: unexpected argument '-' found
```

Codex CLI itself works correctly. The failure appears to be in the relay wrapper argument handling on Windows.

## Environment

* OS: Windows
* Shell: PowerShell / Claude Code shell
* Codex CLI: `0.141.0`
* Node: running `relay.mjs` directly
* User profile path contains a space: `Mahmoud Sabry`

## What happens

`relay.mjs` builds Codex arguments similar to:

```text
codex exec --json -o <finalPath> -s <sandbox> -
```

When `<finalPath>` is created under the default Windows temp directory, it may contain a space because the Windows user profile path contains a space.

Example:

```text
C:\Users\Mahmoud Sabry\AppData\Local\Temp\delegate-relay\...\final.txt
```

On Windows, the relay launches Codex through the shell. This can cause the space-bearing `-o <finalPath>` argument to be split incorrectly. After that, the trailing `-` stdin sentinel is parsed in the wrong position, and Codex exits with:

```text
error: unexpected argument '-' found
```

## Important note

`codex exec -` itself is valid and works manually. The issue is not Codex CLI accepting stdin. The issue is the relay wrapper’s Windows command construction when an argv token contains spaces.

## Reproduction

From a Windows account with a space in the user profile path:

```powershell
$Skill = "$env:USERPROFILE\.claude\skills\codex-delegate"
$Relay = "$Skill\scripts\relay.mjs"
$Brief = "C:\codextmp\brief.txt"
$Repo = (Get-Location).Path

New-Item -ItemType Directory -Force C:\codextmp

Set-Content -Path $Brief -Value @"
Say exactly: PING_FROM_CODEX
Do not edit files.
Do not create files.
"@

node $Relay --brief $Brief --cd $Repo --read-only
```

## Actual result

The relay fails:

```text
error: unexpected argument '-' found
```

The relay result is similar to:

```text
status: failed
exitCode: 2
finalMessage: ""
```

No final Codex message is captured.

## Expected result

The relay should work even when the default temp output path contains spaces.

Expected output:

```text
relay: completed (exit 0)
finalMessage: PING_FROM_CODEX
touchedFiles: []
```

## Workaround

Passing an explicit output directory with no spaces works:

```powershell
node $Relay --brief $Brief --cd $Repo --read-only --out-dir C:\codextmp
```

With that workaround, the relay completes successfully:

```text
status: completed
exitCode: 0
touchedFiles: []
finalMessage: PING_FROM_CODEX
```

## Local fix that worked

I patched my local `relay.mjs` to avoid using Windows shell argument concatenation with an unquoted argv array.

The local fix:

* Preserves the existing non-Windows behavior.
* On Windows, launches through `cmd.exe /d /s /c`.
* Builds a command string where each argument is explicitly quoted when needed.
* Keeps the brief sent through stdin.
* Preserves the relay outputs:

  * `result.json`
  * `events.jsonl`
  * `final.txt`
  * `touchedFiles`
  * `stderrTail`
  * `finalMessage`

Suggested implementation shape:

```js
function quoteForCmd(arg) {
  const s = String(arg);
  if (s.length === 0) return '""';
  if (!/[\s&()^|<>"]/u.test(s)) return s;
  return `"${s.replace(/"/g, '""')}"`;
}

function spawnCodex(argv, opts) {
  if (process.platform !== "win32") {
    return spawn("codex", argv, {
      cwd: opts.cd,
      stdio: ["pipe", "pipe", "pipe"],
    });
  }

  const commandLine = ["codex", ...argv].map(quoteForCmd).join(" ");

  return spawn("cmd.exe", ["/d", "/s", "/c", commandLine], {
    cwd: opts.cd,
    stdio: ["pipe", "pipe", "pipe"],
    windowsHide: true,
  });
}
```

Then replace the current Windows `shell:true` spawn with:

```js
const child = spawnCodex(argv, opts);
```

## Why this matters

This affects Windows users whose user profile paths contain spaces. The relay works when `--out-dir` points to a no-space path, but fails with the default temp output path.

I’m happy to open a PR with the local patch if that approach looks acceptable.

---

## Additional implementation information

The Windows relay must handle temp paths with spaces as single arguments and create output artifacts without allowing collisions, symlink substitution, or access by unrelated local users. Preserve stdin and output-file behavior when the profile path contains spaces.
