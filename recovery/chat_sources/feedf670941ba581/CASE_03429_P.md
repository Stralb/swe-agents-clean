Harden generated writes against symlink targets

## Problem
Several generated-output paths still write with plain `fs.writeFile` or helper writers that do not reject a symlink at the final destination. The shared `writeGeneratedFile`/`backupFile` path rejects symlinked output files, but direct writers bypass that protection when backups are disabled.

Examples include native MCP JSON/TOML writers and agent-specific settings/config writers. A project-local path such as `.cursor/mcp.json` or `opencode.json` can be a symlink to a file outside the project; `ruler apply --no-backup` can then overwrite the symlink target.

## Expected
All Ruler-managed writes should refuse to write through a symlinked final path, regardless of backup settings.

## Suggested fix
Route direct generated writes through a symlink-safe helper, and add integration coverage for MCP/config destinations with `--no-backup`.

Filed by automated review run.

---

## Additional implementation information

Generated configuration writes and any staging or backup files must not allow a different user or an attacker-controlled symlink to substitute the file being written. Temporary files should be created with restricted access and safe ownership, and final destinations must reject symlinks.
