# Bug Report: BYOK API key cannot be saved on Windows (v0.16.1)

**Status:** Ready to file — https://github.com/nexu-io/open-design/issues
**Date:** 2026-08-02
**App version:** 0.16.1 (latest release, installed 2026-07-25)
**Platform:** Windows x64 (desktop app, Electron)

## Title

BYOK (bring-your-own-key) credentials cannot be saved on Windows — runs silently fall back to Open Design Cloud billing

## Symptom

1. Settings → Execution mode → BYOK → enter DeepSeek API key → shows saved
2. Closing and reopening Settings: key field is empty; execution mode reverts to "Local CLI"
3. `start_run` runs fail with **"insufficient balance — your Open Design Cloud balance has run out"** because they bill the cloud account instead of using the user's key

## Evidence (what was checked)

- `app-config.json` — no credential keys (only `agentModels/amr/model`)
- `app.sqlite` — 0 occurrences of `deepseek`, 0 `sk-*` strings
- `<dataDir>/byok/` — directory does not exist (never created)
- Windows Credential Manager (`cmdkey /list`) — no Open Design entries
- App data dirs — no web/localStorage credential stores

## Root cause (from source)

`apps/daemon/src/byok/credential-service.ts`:

```typescript
export function createPlatformByokSecretBackend(platform, dataDir) {
  if (platform === 'darwin') return new MacOsKeychainBackend();
  if (platform === 'linux') return new LinuxSecretServiceBackend();
  if (platform === 'win32' && dataDir) {
    return new RetiredWindowsSecretCleanupBackend(
      path.join(dataDir, 'byok', 'secrets'),
    );
  }
  return new UnavailableSecretBackend(platform);
}
```

`RetiredWindowsSecretCleanupBackend extends UnavailableSecretBackend` — it inherits `set()` which **throws** `"Secure credential storage is unavailable on this system."` and only overrides `delete()` (legacy `.bin` cleanup). So on Windows the BYOK save path always fails; the UI does not surface the error.

## Expected behavior

- Windows should persist BYOK secrets (e.g., DPAPI-encrypted file, Windows Credential Manager, or `cmdkey`)
- The UI should surface a clear error when the secret backend is unavailable (not silently "saved")

## Suggested fix

Implement a real Windows backend (DPAPI via `CredProtect` / `libsodium`-style encrypted file, or Credential Manager), or at minimum surface the `UnavailableSecretBackend` error in the Settings UI and disable the BYOK form on Windows.

## Workaround tried / pending

- `DEEPSEEK_API_KEY` user environment variable + app restart (per deploy docs for Docker) — pending test
