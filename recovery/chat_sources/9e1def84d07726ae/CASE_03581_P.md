feat: AI Commentary during workflow execution

## Summary

Add a **Commentary AI** that observes workflow execution in real-time and narrates what's happening via a chat panel. The Commentary AI is a separate, independent AI session from the Execution AI — it watches from the outside and explains to the viewer.

## Motivation

There is an **information asymmetry** between the workflow designer and the person watching it run (operator/team member). What's obvious to the designer is a black box to the viewer. By having a **separate AI** observe and explain — rather than the execution AI explaining itself — this asymmetry is bridged. The independence of the observer is the key differentiator.

### How this changes development

1. **Team observation**: When a team watches a workflow run while one person operates, everyone understands what's happening without the operator having to explain. Reduces communication overhead during live execution.

2. **Asynchronous review**: Commentary logs persist as a natural-language record of what happened. Anyone who wasn't present can review later — far more accessible than reading raw JSONL transcripts.

3. **Anomaly awareness**: While the operator focuses on execution, the Commentary AI can surface patterns like "retrying the same API for the 3rd time" or "unexpected error occurred" — observers may notice issues before the operator does.

4. **Onboarding & learning**: New team members can watch workflow execution with live commentary to learn how AI agent workflows operate in practice.

## Architecture

```

│ VSCode Extension Host                                    │
│                                                          │
│  1. Start execution                                      │
│     sessionId = crypto.randomUUID()                      │
│     terminal.sendText(                                   │
│       `claude --session-id "${sessionId}" "/${name}"`)   │
│                                                          │
│  2. JSONL file watching                                  │
│     fs.watch(~/.claude/projects/{path}/{sessionId}.jsonl)│
│     → Parse new lines                                    │
│     → Filter meaningful events + buffer                  │
│                                                          │
│  3. Commentary AI invocation (default: haiku)            │
│     1st call: claude -p --model haiku --output-format json│
│       "Workflow definition: {...}                         │

│                                                          │
│     Subsequent: claude -p --resume {commentarySessionId} │

│                                                          │
│  4. Display in Webview                                   │
│     postMessage(POST_COMMENTARY, { text })               │
│                                                          │
```

### Key Design Decisions

| Aspect | Approach |
|--------|----------|
| **Asymmetry** | Execution AI and Commentary AI are fully independent. Execution AI has no knowledge of the commentator |
| **Session ID** | Pre-assigned via `--session-id` with `crypto.randomUUID()` (✅ verified) |
| **Execution tracking** | Extension Host watches JSONL file via `fs.watch` |
| **Commentary generation** | `claude -p --model haiku` with `--resume` for session continuity (✅ verified) |
| **Commentary display** | Extension Host → postMessage → Webview side panel |
| **MCP** | Not required — Extension Host mediates everything |
| **User burden** | None — no hooks setup, no additional configuration |

## Implementation Plan

### Phase 1: JSONL Watcher Service

- Modify `terminal-execution-service.ts` to include `--session-id` in `claude` invocation
- Create `jsonl-watcher-service.ts`:
  - `fs.watch` on `~/.claude/projects/{path}/{sessionId}.jsonl`
  - Parse new lines, filter meaningful events (`assistant`, `tool_use`, `error`, `progress`)
  - Buffer events (by interval or line count) before forwarding

### Phase 2: Commentary AI Service

- Create `commentary-ai-service.ts`:
  - `child_process.spawn` to invoke `claude -p --model haiku --output-format json`
  - 1st call: send full workflow definition + system prompt (commentator role)
  - Subsequent calls: `--resume {commentarySessionId}` + buffered JSONL diff
  - Parse stdout JSON response for commentary text

### Phase 3: Webview UI (Side Panel)

- Create `CommentaryPanel.tsx`: slide-in panel on the right side of the canvas
- Reuse existing `MessageList` / `MessageBubble` components (✅ confirmed reusable)
- Read-only (no `MessageInput` needed)
- Create `commentary-store.ts` (Zustand) for commentary state management

### Phase 4: ON/OFF Toggle

- Add toggle inside **Claude Code Run button's sub-menu** in `Toolbar.tsx`
- Claude Code-only feature — not visible to Copilot/Codex/Gemini users
- Toggle state managed in workflow-store

## JSONL Transcript Format (investigated)

```jsonl
// System init (contains session_id)
{"type": "system", "subtype": "init", "session_id": "..."}

// User message
{"type": "user", "message": {"role": "user", "content": "..."}}

// Assistant response (text + tool use)
{"type": "assistant", "message": {"role": "assistant", "content": [
  {"type": "text", "text": "..."},
  {"type": "tool_use", "name": "Bash", "input": {"command": "npm run build"}}
]}}

// Tool result
{"type": "user", "message": {"content": [
  {"type": "tool_result", "tool_use_id": "...", "content": "...", "is_error": false}
]}}

// Progress (long-running tool)
{"type": "progress", "data": {"type": "bash_progress", "output": "..."}}
```

## Technical Verification Results

### `--session-id` assigns UUID to new session ✅
```bash
SESSION_ID=$(uuidgen)
claude --session-id "$SESSION_ID" -p "hello" --output-format json
# → response session_id matches the specified UUID
```

### `--resume` maintains context across calls ✅
```bash
# 1st call
claude -p "secret word is pineapple" --model haiku --output-format json
# → get session_id

# 2nd call
claude -p "What was the secret word?" --resume {id} --model haiku --output-format json
# → correctly answers "pineapple"
```

### JSONL file path pattern ✅
```
~/.claude/projects/{encoded-project-path}/{session-id}.jsonl
```

## Additional implementation information

The commentary observer must handle execution transcript files being appended, replaced, truncated, or removed while it reads. State and file handles must correspond to the same underlying transcript throughout each processing operation; avoid losing or duplicating events under concurrent updates.
