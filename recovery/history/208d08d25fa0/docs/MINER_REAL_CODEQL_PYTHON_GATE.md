# Candidate genuine CodeQL Python engine — synthetic, isolated and checksum-verified

The CodeQL integration first passed a separate 15-test fake-CLI no-network contract: `docs/MINER_ARCHIVED_CODEQL_LOCAL_PROCESS.md`. The subsequent genuine-engine workflow `.github/workflows/synthetic-codeql-real-python.yml` uses the **official CodeQL v2.27.3 Linux x64 bundle**, downloaded from `github/codeql-action` and verified against its GitHub release SHA-256 **`64518dc413c8e7b5733fee2489e830a899bb1e3f28c8873b5869d5cc90164c5c`**. This is a **candidate modern engine** published 20 October 2026, *not an attested historic version or query-pack fingerprint*.

The test runs CodeQL's original `codeql/python-queries:codeql-suites/python-security-extended.qls` suite, using the bundle's built-in query packs and an inert two-commit Python Git fixture. Only a short Python function is added at head that statically connects Flask request arguments to an `os.system` call. The source code is **never executed**; `--build-mode=none` is preserved as in the archived scanner.

The real CLI and the exact unchanged historical `scan_snapshot_with_codeql` function run using the original Git clone/fetch/checkout, database creation and SARIF analysis options (except the clone URL is redirected to an exact local `file://` two-commit fixture). The exact archived `diff_findings`, `filter_findings_to_pr_delta`, `scan_case`, `run_scanner_job`, scanner row insertions and review-stage updates are used on disposable original SQLite. The test must verify at least one real head finding with CWE metadata, an added-line link and the expected original worker status. Scanner failures/missing CodeQL packs cannot be interpreted as zero vulnerabilities.

**Isolation:** Host acquisition and image-building use network access. The scan container runs with `--network none`, non-root user, read-only root and repository, read-only CodeQL bundle mount, all Linux capabilities dropped, `no-new-privileges`, and a temporary RAM-backed /tmp, with CPU/memory/PID limits. Only a generated fixture is scanned; real repository URLs are disallowed.

**Important limitations:** The CodeQL version, query pack compilation caches and base Python image are not the original study's pinned environment. This test covers only Python source with a known synthetic security sink. It does not establish CodeQL parity for JS/TS, Go, Java, C/C++, Ruby or C#, original scanner-positive counts, historical SARIF signatures, or correctness of heuristic PR diff linking. Remaining published research reproduction gates stay open.

**Verified outcome:** [The genuine-engine CI passed](https://github.com/Stralb/arno-research-reproducibility/actions/runs/39639711875). It observed exactly the expected fabricated case's real CodeQL `py/command-line-injection` finding on `src/app.py:9`, tagged `external/cwe/cwe-078,external/cwe/cwe-088`, and verified original worker/SQLite persistence. This proves the synthetic Python execution pathway, not the original study's historical warning dataset.


## 21 October CI failure and isolated bundle permission correction

The first genuine CodeQL run ([failed CI log](https://github.com/Stralb/arno-research-reproducibility/actions/runs/39632545550)) discovered a genuine `py/command-line-injection` alert at synthetic head (`src/app.py:9`, CWE-078/CWE-088) but **did not pass**: the original baseline scanner hit its **600-second fixture timeout**. Log evidence repeatedly shows `java.nio.file.AccessDeniedException` opening the official bundle's precompiled `.bytes.qlx` query plans under non-root execution from a read-only mount. The engine therefore compiled security-extended queries from source instead of reading the precompiled plans.

The CI host now makes only the **SHA-verified, throwaway extracted CodeQL bundle** world-readable/searchable with `chmod -R a+rX`, checks that precompiled plans exist and are readable, and continues to bind-mount the bundle **read-only** in the non-root, network-disabled scan container. This changes no original historical function, production DB, repository or original study data. The 600-second timeout and both base/head `status=ok` assertions remain mandatory. **The correction is now verified**: the [next real CodeQL CI run passed](https://github.com/Stralb/arno-research-reproducibility/actions/runs/39639711875) all assertions, scanning both snapshots in **64.528 seconds**. There were no `AccessDeniedException` messages on that run. Neither the historical source nor the original CodeQL query pack version was changed.
