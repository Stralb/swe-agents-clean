# v2.2 Change-Operation Miner

## Purpose

The previous broad EDA successfully mapped the corpus but also demonstrated an important failure mode: statistically stable **states** are often scientifically trivial. v2.2 fixes the discovery target itself.

**Old target:** correlations, latent-state co-occurrence, token frequency, path components, partial-hunk syntax states.

**New target:** **what was actually removed, what was actually added in its place, which distinct files change together, and which normalized edit operations recur across unrelated repositories.**

The run is still completely outcome-blind.

## Primary outputs

- `01_blocks/change_blocks.parquet` (or `.pkl` fallback): real diff replacement/add/delete blocks.
- `02_transformations/transition_candidates.csv`: recurring concrete `removed -> added` operations.
- `02_transformations/dependency_transition_summary.csv`: factual recurring package value changes.
- `03_flows/artifact_flow_metrics.csv`: issue -> PR -> patch grounding/novelty metrics.
- `04_cochange/cross_file_cochange_surprises.csv`: repository-conditioned relationships requiring distinct changed files.
- `05_templates/cross_repo_code_templates.csv`: repeated added and replacement code templates across repositories.
- `06_validate/validated_transitions.csv`: within-repo null + repo bootstrap evidence.
- `06_validate/validated_cochanges.csv`: repo-conditioned bootstrap evidence.
- `07_catalog/SCIENTIFIC_SHORTLIST_V22.csv`: small family-balanced output for interpretation.
- `V2_2_DISCOVERY_REPORT.md`: deterministic summary.

## What v2.2 intentionally does not do

- no clustering;
- no generic all-pairs correlation sweep;
- no itemset mining of `feature absent` states;
- no crawler/query metadata;
- no AST parsing of incomplete diff fragments;
- no scanner/security outcome access;
- no LLM classification;
- no pre-written question such as "do agents add tests?".
